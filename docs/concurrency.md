# Concurrency and cancellation

`src/lib/concurrency.ts` exposes a FIFO `createConcurrencyLimiter(limit)`. Its task callback receives an `AbortSignal`; each submission accepts optional `{ signal, timeoutMs }`. Defaults remain no deadline and no cancellation. Existing no-argument callbacks need no changes. `timeoutMs` is an integer from 0 through 2147483647 and includes queue time; zero schedules an immediate timer, not a synchronous rejection.

A pre-aborted or queued-aborted submission never executes. Cancellation removes its queue entry, timeout, and external listener. Active cancellation rejects the caller immediately and aborts the callback signal, but the active slot remains occupied until the callback settles. Ignoring the signal therefore does not free capacity. Cleanup belongs in the callback's `finally`; the limiter cannot stop filesystem or SQLite work. Abort uses the supplied signal's reason (normally `AbortError`), and deadlines use `DOMException` with name `TimeoutError`. Completion and cancellation use first-settlement-wins Promise semantics. Synchronous throws and async rejections release capacity and drain the queue.

No source mutation opts into a default timeout: deleting source files or committing database transactions must finish cleanup before capacity is reused. The transcript scheduler also retains its existing completion-based contract. In particular, do not nest a caller-rejecting limiter inside another limiter and assume rejection means its underlying work stopped. Callers opting into cancellation must propagate the signal to cooperative operations and await their cleanup; do not detach work from the returned promise. `mapWithConcurrency` keeps its existing contract: stop admitting after failure and await all admitted workers.

Transcript loading requires an integration identity. Each source has its own FIFO queue, with a FIFO aggregate ceiling. `SPIRACHA_TRANSCRIPT_LOAD_CONCURRENCY` defaults to 3 per integration and clamps at 16; invalid/nonpositive values fall back to 3. The aggregate ceiling is `min(32, max(16, perIntegration * 2))`. This applies to development and packaged servers. Set the environment before starting the server; a restart applies changes consistently. Increase the setting only after measuring wait times and memory usage. `SPIRACHA_TRANSCRIPT_LOAD_LOGS=1` enables per-source active/queued counts, wait times, and execution duration; default operation is quiet. A source can place only its bounded admitted set into the global FIFO, so later arrivals cannot continually overtake a waiting source. This bounds admission, not individual transcript size.
